1. Executive Summary & Product Vision

Quake-RS is a clean-room, 100% memory-safe Rust reimplementation of id Software’s 1996 Quake engine (id Tech 2) engineered around modern GPU-driven rendering and compute pipelines.

While classic C-based source ports (QuakeSpasm, Ironwail, vkQuake, DarkPlaces) have kept Quake playable on modern operating systems, they inherit three decades of global mutable state, unsafe pointer arithmetic in binary file parsers, and CPU-bound rendering paradigms. Quake-RS eliminates all C dependencies and memory-unsafety bugs while transforming the renderer into a showcase for the modern Rust GPU ecosystem—combining portable WebGPU (wgpu) pipelines, GPU-driven bindless geometry culling, compute-based 8-bit software palette emulation, and inline hardware ray queries.

Users can switch at runtime between two rendering personalities:

  1. Abrash Mode (Authentic Compute Software Renderer): A cycle-accurate, GPU-compute recreation of Michael Abrash’s 1996 software rasterizer (8-bit indexed colormap.lmp, surface-cached dynamic lightmaps, underwater screen warp, and affine/perspective span rules) running at native 4K+ and greater than 500 FPS.
  3. Slipgate Mode (Modern GPU-Driven Hybrid Ray-Traced Renderer): Full hardware-accelerated ray-traced shadows, real-time global illumination bounce from lava/teleporters, mesh-shader geometry pipelines, and GPU-simulated particle systems—all while preserving Quake’s iconic 64-unit texel grid aesthetic.

2. Problem Statement & Strategic Opportunity

2.1 Limitations of Legacy C Ports

  • Memory Safety & Security Vulnerabilities: Original .PAK, .BSP, .MDL, .DEM, and progs.dat (QuakeC) loaders rely on raw fread casts into C structs and unchecked stack buffers. Malformed maps, community mods, or malicious network packets can trigger buffer overflows or arbitrary code execution.
  • Global Mutable State & Single-Threaded Bottlenecks: Classic id Tech 2 interleaves client state, server state, audio mixing, and renderer traversal through global C variables (cl, sv, r_refdef), preventing safe multi-core parallelization.
  • Legacy CPU-Driven Draw Loops: Traditional ports walk the Binary Space Partitioning (BSP) tree and Potentially Visible Set (PVS) on the CPU every frame, submitting thousands of small state-changing draw calls and stalling modern GPUs.

2.2 Why the Rust GPU Ecosystem Now?

The Rust GPU landscape has matured into a production-ready foundation with clear architectural trade-offs:

  • Mature Cross-Platform Portability (wgpu v30+): wgpu ships major releases with native backends for Vulkan, Metal, DirectX 12, and OpenGL ES, alongside WebAssembly/WebGPU for zero-install browser play. It also exposes native-only extensions (FeaturesWGPU) for hardware Ray Queries and Mesh/Task Shaders.
  • Pragmatic Shader & Compute Strategy: Because the original EmbarkStudios/rust-gpu repository was archived in October 2025, relying solely on rust-gpu for all graphics shaders carries toolchain risk. However, next-generation Rust GPU efforts—such as CubeCL for portable compute kernels and VectorWare’s Rust GPU advancements supporting std::thread warp specialization and async/await on GPU hardware—unlock shared Rust types and complex GPU-side orchestration. Quake-RS adopts a resilient dual-track GPU architecture: WGSL + naga as the guaranteed portable baseline, paired with CubeCL / SPIR-V Rust kernels for advanced compute workloads.

3. Goals, Non-Goals & Success Metrics

3.1 Product Goals

  • 100% Asset & Mod Compatibility: Load unmodified retail and shareware id1/pak0.pak and pak1.pak, plus massive modern community mods (Arcane Dimensions, Copper, Alkaline) requiring BSP2 and RMQ protocol limits.
  • Zero unsafe in Parsers & VM: Enforce #![forbid(unsafe_code)] across all file format parsers, network packet decoders, and the progs.dat QuakeC virtual machine.
  • GPU-Driven Frame Pacing: Move frustum culling, PVS bitmask evaluation, lightmap atlas updates, alias model keyframe interpolation, and particle physics entirely to the GPU.
  • Browser Playability: Compile the full engine to wasm32-unknown-unknown targeting WebGPU so players can drop a shareware .PAK into a browser tab and play immediately.

3.2 Non-Goals

  • Altering Core Gameplay Physics: Bunny-hopping, air-strafing, ramp-sliding, and entity collision quirks must remain 100% bit-compatible with standard NetQuake/QuakeWorld rules and existing .dem recordings.
  • Proprietary Single-Vendor Lock-In: No hard dependency on NVIDIA-only CUDA (cudarc / rust-cuda) for core gameplay or rendering; all GPU features must run on AMD, Intel, Apple Silicon, and NVIDIA hardware via Vulkan/Metal/DX12/WebGPU.

5. Detailed GPU Feature Requirements

5.1 GPU-Driven Bindless BSP & Meshlet Pipeline (P0)

In classic Quake, the CPU traverses the BSP tree, decompresses run-length encoded PVS bitvectors, and issues individual draw calls per texture chain. Quake-RS moves the entire world geometry into a unified GPU-driven pipeline:

  • Single Mega-Buffer Allocation: On map load, all .BSP brush vertices, lightmap coordinates, and .MDL alias model frames are uploaded into persistent GPU storage buffers. All mipmapped .WAD textures are placed into bindless texture arrays.
  • Compute Culling & Multi-Draw Indirect (MDI): A GPU compute pass evaluates the camera leaf’s PVS bitmask, frustum planes, and a hierarchical depth buffer (Hi-Z pyramid) from the previous frame. Visible brush surfaces and meshlets are appended atomically to an IndirectDrawBuffer via dispatch_workgroups_indirect and drawn in a single multi_draw_indexed_indirect_count call.
  • Mesh Shader Fast-Path (Native Opt-In): On hardware supporting FeaturesWGPU mesh and task shaders, brush geometry and high-poly modded .MDL/.MD3 models bypass the traditional vertex input assembler, using task shaders for cluster culling and mesh shaders for primitive emission.

5.2 "Abrash Mode": Compute-Driven 8-Bit Software Emulation (P0)

Modern OpenGL/Vulkan ports often approximate Quake’s 8-bit look with a simple post-process LUT, which fails to capture how original surface caching (d_surfaces) combined mipmapped base textures and dynamic lightmaps into the 256-color palette.lmp via colormap.lmp before rasterization.

  • GPU Surface Cache Compute Pass: A CubeCL / WGSL compute pass dynamically composites dirty .BSP surfaces into a virtual GPU surface cache, snapping texels to the exact 16x16 lightmap grid and indexing through colormap.lmp in 8-bit integer space.
  • Sub-Pixel Span & Underwater Warp Compute: Screen-space underwater sinusoidal warping (r_waterwarp) and 8-bit screen blends (damage flash, power-up tints via v_cshift) are executed in a tile-based compute shader writing directly to a storage texture before presentation.

5.3 "Slipgate Mode": Hardware Ray-Traced Lighting & Shadows (P1)

Using wgpu ray-tracing acceleration structures and inline ray queries:

  • Acceleration Structure Hierarchy:

  • Static BLAS (Bottom-Level Acceleration Structure): Built once per map load for static world .BSP geometry.
  • Dynamic BLAS: Rebuilt or refitted each frame on the GPU for moving brush entities (func_door, func_plat, func_train) and keyframe-interpolated .MDL monsters/weapons.
  • TLAS (Top-Level Acceleration Structure): Updated every frame with active entity transforms.
  • Hybrid Lightmap + Ray Query Pipeline: Original baked .BSP lightmaps are preserved for artistic mood, or optionally replaced by real-time path-traced indirect bounce from emissive surfaces (lava, slime, slipgates, torches). Point lights (rockets, nails, lightning gun arcs, muzzle flashes) trace shadow rays via inline ray queries with pixel-snapped penumbras that respect Quake’s low-res texel density.

5.4 GPU Compute Particles, Turbulent Liquids & MDL Morphing (P0)

  • Compute Particle Simulator: Rocket trails, blood splatters, teleporter bursts, and explosion sparks (up to 1,000,000 active particles in heavy mods) are simulated in a double-buffered GPU compute storage buffer with full .BSP leaf-plane collision detection on the GPU.
  • MDL Vertex Interpolation & Motion Vectors: Classic .MDL models store quantized 8-bit vertex coordinates (trivertx_t) with normal indices. A vertex/compute pre-pass dequantizes, lerps between frame_a and frame_b, and outputs per-vertex screen-space velocity vectors to support optional temporal anti-aliasing (TAA) and motion blur.

5.5 GPU Acoustic Ray-Tracing (P2)

  • BSP Waveguide Reverb: A low-priority asynchronous compute queue fires 256 acoustic rays per audio frame from the player camera and active sound emitters against the .BSP collision hull. Returning bounce distances and material absorption coefficients (metal, wizard brick, water, sky) parameterize a real-time convolution/FDN reverb filter on the audio thread, recreating authentic 1990s Aureal A3D / EAX spatial acoustics without proprietary hardware.

6. Host Engine Subsystem Requirements (Safe Rust)

6.1 Zero-Copy, Memory-Safe Asset Pipeline

  • Supported Formats: PAK, WAD2, BSP29 (vanilla), 2PSB / BSP2 (expanded 32-bit limits for modern maps), MDL (v6), SPR (v1), LMP, and WAV.
  • Implementation: Built using nom and zerocopy with strict bounds validation. Any out-of-bounds offset, cyclic BSP node index, or truncated lump returns a structured EngineError::CorruptAsset diagnostic rather than panicking or reading uninitialized memory.

6.2 Deterministic Sandboxed QuakeC VM (progs.dat)

  • Bytecode Interpreter & JIT: Loads standard v6 progs.dat bytecode and extended FTE/QSS opcodes used by Arcane Dimensions and Copper.
  • Safety Guarantees: Entity handles (edict_t), string table offsets, and function pointers are validated through generational arena indices (slotmap). Mods cannot read or write host memory outside the VM sandbox.
  • Fixed-Tick Determinism: Server simulation runs at an invariant 72 Hz tick rate (0.013888... seconds per step) while the wgpu render loop runs unlocked, interpolating entity transforms and camera angles between the two most recent server snapshots.

6.3 Networking & WebRTC/QUIC Transport

  • Protocol Parity: Supports legacy NetQuake UDP protocol (protocols 15, 666, and 999) for compatibility with existing servers and .dem files.
  • Modern Encrypted Transport: Adds an optional quinn (QUIC) and WebTransport layer so browser WebGPU clients can join multiplayer matches seamlessly with NAT traversal and zero head-of-line blocking.

Native-only features like hardware Ray Queries and Mesh Shaders (FeaturesWGPU) are unavailable in standard browser WebGPU. Query adapter capabilities at startup and automatically fall back to compute-culled vertex pipelines and classic lightmaps on WebGPU.

Keep all authoritative gameplay physics, collision hull checks (SV_Move), and QuakeC execution on the CPU using strict IEEE-754 32-bit floats (f32) matching id Tech 2 truncation rules; restrict GPU compute strictly to visual and acoustic simulation.
